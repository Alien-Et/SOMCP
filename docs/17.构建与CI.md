## c++_static 的原因

```kotlin
cppFlags += listOf("-std=c++17", "-fexceptions", "-frtti", "-Wall", "-Wextra")
// c++_static keeps every self-built .so self-contained
```

加固（VMP / Dex2C）重打包可能把 `libc++_shared.so` 从 `lib/` 里删掉。
此时若 `librz_native.so` 是 `c++_shared` 链接的，`dlopen` 会报
`cannot locate symbol _ZTVNSt6__ndk1...` 直接崩启动。

## ABI 分包

```kotlin
splits {
    abi {
        isEnable = true
        reset()
        include("arm64-v8a", "armeabi-v7a", "x86", "x86_64")
        isUniversalApk = true
    }
}
excludes += setOf("lib/armeabi/**", "lib/mips/**", "lib/mips64/**")
```

NDK 29 已不支持 `armeabi`，universal 包如果带上死目录会导致 Dex2C 步骤
`abortOnError`。

## 签名

`signingConfigs.release` 优先读环境变量（CI 用），fallback 到本地 keystore。

CI 的 5 个 secrets：

| Secret | 内容 |
| --- | --- |
| `KEYSTORE` | base64 编码的 JKS |
| `ALIAS` | key alias |
| `ALIAS_PASSWORD` | key 密码 |
| `PASSWORD` | store 密码 |
| `TM` | 时间戳 / 辅助字段 |

`LRP_API_KEY` 可选（LLM release notes 用）。

keystore 恢复的关键是**去空白**：

```bash
printf '%s' "$KEYSTORE_B64" | tr -d '[:space:]' | base64 -d > release/so-reverse-mcp-release.jks
keytool -list -keystore release/so-reverse-mcp-release.jks ...
```

漏了 `tr -d '[:space:]'` 会 `base64: invalid input`。

## 工具链版本：一处定义，全局引用

三个构建工作流（`build.yml` / `release.yml` / `test-v11.yml`）**必须**用同一套
JDK、Gradle、Android platform、build-tools、NDK、cmake。checks 用 A 版本编译
通过、release 用 B 版本发布，checks 的绿灯就证明不了 release 能构建 —— 这正是
历史上踩过的坑：`test-v11.yml` 少装 Unidbg 与 rz-ghidra 两步时 checks 全绿，
而只有 release 包里带着这两样。

因此每个工作流在**顶层 `env:` 块**里声明一次，下面一律用 `$SOMCP_*`
（`run:` 里）或 `${{ env.SOMCP_* }}`（action 输入里）引用：

| 变量 | 值 | 说明 |
| --- | --- | --- |
| `SOMCP_JAVA_VERSION` | `17` | AGP 8.x 要求 |
| `SOMCP_GRADLE_VERSION` | `9.6.1` | 与 `gradle/wrapper/gradle-wrapper.properties` 一致 |
| `SOMCP_ANDROID_PLATFORM` | `platforms;android-36` | |
| `SOMCP_BUILD_TOOLS` | `build-tools;36.0.0` | |
| `SOMCP_NDK` | `ndk;29.0.14206865` | 同时被 `tools/blutter-matrix/matrix-config.json` 硬 pin |
| `SOMCP_CMAKE` | `cmake;3.22.1` | 必需，见上文 CMake 4.x 一节 |

`blutter-engines.yml` 不构建 APK（无 JDK / Gradle / SDK platform），只声明
它真正需要的 `SOMCP_NDK` —— 那个值也必须与三个构建工作流相同，因为它产出的
runner 会被用该 NDK 构建的 APK `dlopen`。

### 守卫：`tools/check-workflow-versions.py`

```bash
python3 tools/check-workflow-versions.py
```

退出码 0 = 一致，1 = 有问题。它查三件事：

1. 每个工作流都声明了它该有的 `SOMCP_*`；
2. `env:` 块之外没有同一版本的硬编码副本（注释里的说明文字不算）；
3. 同名 `SOMCP_*` 在所有工作流里取值相同。

`test-v11.yml` 的 `Workflow toolchain version consistency` 步骤会跑它，
所以在 PR 阶段就会挡住「某个工作流被单独改了版本」这类回归。

新增一个需要 pin 的版本时，改三处：`tools/check-workflow-versions.py` 的
`PINNED` / `EXPECTED` 两个表、三个工作流的 `env:` 块（保持字节一致）、
以及本节的表格。

### 已删除的 `test.yml` / `test-v2..v10`

### 与 release.yml 的差异

`checks` 只负责「代码能不能构建」，不发布产物，所以它比 `release.yml`
多出 lint / ktlint / 合规 / PR 检查 / 单测，少了 release notes 与上传。
两个工作流的原生构建步骤（Rizin+LIEF、Unidbg、rz-ghidra、Blutter）必须
保持一致 —— 否则 `checks` 全绿也证明不了发布产物可用。历史上就踩过这个坑：
`test-v11.yml` 早期没有 Unidbg 与 rz-ghidra 两步，checks 通过但
`lief_api` / `emulate_*` / `unidbg_*` 在真机上全是不可用。

### setup-gradle 的 504 重试

`gradle/actions/setup-gradle@v4` 从 `services.gradle.org` 拉发行包。该服务
偶发 504，action 自身只重试两次（约 35 秒）就判定失败，整条流水线在第一个
业务步骤之前就红了（实测 run 42466197798）。三个工作流都改成
`continue-on-error: true` + 一条 `if: steps.setup-gradle.outcome == 'failure'`
的重复步骤，把上游抖动挡在门外。

### SDK 包

```yaml
packages: |
  platforms;android-36
  build-tools;36.0.0
  ndk;29.0.14206865
  cmake;3.22.1
```

`cmake;3.22.1` 必须装 SDK 版本 —— runner 自带的是 CMake 4.x，而 pin 住的
老代码树（capstone 4.0.2、keystone 及其内置 LLVM）里仍写着
`cmake_policy(SET CMP0051 OLD)`，4.x 直接当错误处理：

```text
Policy CMP0051 may not be set to OLD behavior because this version of CMake
no longer supports it.
```

`build.yml` / `release.yml` 一直装了这个包；`test-v11.yml` 早期漏装，
导致它的 Unidbg 步骤回落到系统 cmake 4.4 并在 keystone 配置阶段挂掉。
现在三个工作流都装了。

脚本侧另有一层兜底：`build-unidbg-native.sh`、`build-native-android.sh`、
`tools/blutter-matrix/build_capstone_android.sh` 都会在 configure 前把
`third_party/` 下（递归，跳过 `.git/`）的 `CMakeLists.txt` 就地规范化 ——
`cmake_policy(SET CMPxxxx OLD)` 改 `NEW`、`cmake_minimum_required(VERSION <3.5)`
抬到 `3.5` —— 并额外传 `-DCMAKE_POLICY_VERSION_MINIMUM=3.5`。改写是幂等的
（第二次运行 `patched=0`），只动 submodule 工作副本，主仓库无改动。

### Rizin 自动取最新

```bash
LATEST_TAG=$(git ls-remote --tags --sort=-v:refname https://github.com/rizinorg/rizin.git \
  | grep -oE 'refs/tags/v[0-9]+\.[0-9]+\.[0-9]+$' | head -1 | sed 's#refs/tags/##')
```

用到 Rizin 源的三处都是这个写法：`build.yml` / `release.yml` /
`test-v11.yml`（`test.yml` 与 `test-v2..v10` 已删除）。

### Unidbg native 的 32 位处理

```yaml
for abi in arm64-v8a armeabi-v7a x86 x86_64; do
  bash build-unidbg-native.sh --abi $abi
done
# 64 位需要 unicorn
for abi in arm64-v8a x86_64; do
  test -f app/src/main/jniLibs/$abi/libunicorn.so
done
# 32 位必须没有 unicorn
for abi in armeabi-v7a x86; do
  test ! -f app/src/main/jniLibs/$abi/libunicorn.so
done
```

### CMake 4.x 兼容

`build-unidbg-native.sh` 和 `build-rz-ghidra-android.sh` 都加了：

```bash
-DCMAKE_POLICY_VERSION_MINIMUM=3.5
```

`build-unidbg-native.sh` 的 `build_one` 里还有幂等 sed：

```bash
sed -i 's/cmake_policy(SET CMP0048 OLD)/cmake_policy(SET CMP0048 NEW)/' CMakeLists.txt
sed -i 's/cmake_minimum_required(VERSION 2\.[0-9]*)/cmake_minimum_required(VERSION 3.5)/' CMakeLists.txt
```

这会**就地修改 submodule**，所以主仓库常显示 `third_party/zhkl-capstone-src`
dirty —— 属预期，不要提交。

## release.yml

在 `build.yml` 基础上多了：

- 缓存原生后端（`Cache native backends`）
- Build Blutter runners（best-effort）
- 生成 release notes（LLM，可 fallback 到 commit 列表）
- 重命名 APK 并生成 `SHA256SUMS`
- `softprops/action-gh-release@v2` 上传

### 资产命名

```bash
VERSION="${{ inputs.tag || github.ref_name }}"
VERSION="${VERSION#v}"
cp "$f" "release/SOMCP-${VERSION}-${name}.apk"
(cd release && sha256sum SOMCP-*.apk > SHA256SUMS)
```

产物名：

```text
SOMCP-1.0.33-arm64-v8a.apk
SOMCP-1.0.33-armeabi-v7a.apk
SOMCP-1.0.33-x86.apk
SOMCP-1.0.33-x86_64.apk
SOMCP-1.0.33-universal.apk
SHA256SUMS
```

### workflow_dispatch 兜底

```yaml
on:
  push:
    tags: ['v*']
  workflow_dispatch:
    inputs:
      tag:
        description: 'Release tag (e.g. v1.0.0)'
        required: false
```

所有 `github.ref_name` 都改成 `inputs.tag || github.ref_name`。

**为什么需要**：仓库曾经是 fork，fork 期间 tag push 不触发任何 workflow。
即使 `Remove fork network` 之后，用 PAT 推的 tag 也可能不被识别为 push 事件。
手动 dispatch 是最可靠的兜底。

## 本地构建

```bash
# 1) Rizin 源码（非 submodule）
git clone --depth 1 --branch <latest-tag> https://github.com/rizinorg/rizin.git third_party/rizin-src

# 2) 原生依赖
bash build-native-android.sh        # Rizin + LIEF

# 3) Unidbg native（可选，要 emulate_* 才需要）
bash build-unidbg-native.sh --abi arm64-v8a

# 4) 打包
./gradlew :app:assembleDebug
```

### Gradle 增量缓存坑

改完 Kotlin 后 `assembleDebug` 报成功但 dex 里没有新代码 —— 遇到过多次。
**关键验证一律加 `--rerun-tasks`**：

```bash
./gradlew :app:assembleDebug --rerun-tasks
```

验证新代码是否进包：

```bash
unzip -p app/build/outputs/apk/debug/app-arm64-v8a-debug.apk classes3.dex > /tmp/d.dex
grep -qa "新增的字符串常量" /tmp/d.dex && echo OK
```

### CMake 缓存坑

改完 native 代码后如果只删 `app/build/intermediates/cxx`，CMake configure
指纹没变，会直接链接旧的 stub。必须：

```bash
rm -rf app/.cxx app/build/intermediates/cxx
./gradlew :app:assembleDebug --rerun-tasks
```
