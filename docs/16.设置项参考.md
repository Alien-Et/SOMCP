## 迁移

`SettingsStore` 的 `init` 块里做一次性迁移：

```kotlin
// 1) 移除已废弃的 APK MCP 默认配置
if (!prefs.getBoolean("apkNpBridgeRemoved", false)) { ... }

// 2) 本地与局域网直连免 key
if (!prefs.getBoolean("lanNoAuthMigrated_v1", false)) {
    prefs.edit()
        .putBoolean("authEnabled", false)
        .putBoolean("lanNoAuthMigrated_v1", true)
        .apply()
}
```

**迁移原则**：迁移永远不能把安全设置**打开**到更宽松的状态而用户不知情。
上面的免 key 迁移是有意的产品决策（用户明确要求），并记录了迁移标记。

## 工具参数：`so_open` 的 `temporary`

严格说这不是「设置项」，而是一个**工具参数**，但它过去是误导性的，记在这里。

| 值 | 现在的行为 |
| --- | --- |
| `true`（`so_open` 默认） | 标记为 disposable：达到 8 个 workspace 上限时**优先淘汰** |
| `false`（`open_url` 默认） | 与其它 workspace 同优先级，按最久未访问淘汰 |

**历史**：`temporary` 曾经只在 `workspace_overview` 里被回显，**没有任何清理逻辑读取它**，
而 schema 描述写的是「If true, workspace won't persist across restarts」——
可本就没有跨重启持久化机制，所以那句话既无法兑现也无法违背。
描述现已改为反映真实语义（见 `04.引擎运行时.md`）。本磁盘面确实没有 `temporary` 相关的偏好键。
